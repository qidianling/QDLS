# 零基础看懂 QDLS：架构 · 参数 · 优化 · 取舍

> 这份文档写给第一次接触「语音转换（SVC）」的人。
> 读完你应该能回答三个问题：**它是怎么连起来的？每个旋钮是干什么的？我该牺牲什么换什么？**

---

## 第一部分：链接架构

### 1.1 一句话版本

```
你的嘴（QQ / DSH / 控制台）
        ↓ 一句话「唱首失眠」
   [插件] 把歌名交给 [QDLS 面板]
        ↓
   [引擎网关] 下载歌曲 → 分离人声 → 换音色 → 修音 → 后处理
        ↓
   生成 mp3 → 原路返回 → 你收到一条语音
```

### 1.2 四个角色，别记混

| 角色 | 是什么 | 类比 | 端口 |
| --- | --- | --- | --- |
| **控制台（面板）** | 你看到的网页界面 + REST API | 遥控器 + 前台 | 6768 |
| **引擎网关** | Gradio 服务，真正跑模型的地方 | 车间 | 6767 |
| **插件** | AstrBot / DSH 里的薄客户端 | 传话的人 | 无 |
| **隧道** | SSH 反向端口转发 | 从云端回你家的专线 | — |

关键点：**模型只在你自己的电脑上跑**，云端插件只传「歌名」这种文本，音频不出本机。

### 1.3 端口表（最容易搞混的地方）

| 端口 | 谁在听 | 用途 | 谁连它 |
| --- | --- | --- | --- |
| `6767` | 引擎网关（Gradio） | `/convert` 传统翻唱接口 | 旧插件、本地点歌台 |
| `6768` | 控制台 | 网页 UI **和** `/api/v1/*` | 浏览器、AstrBot 插件、MCP |
| `6790` | 安装向导 | 只在安装时出现 | 浏览器 |

> 记住一句：**要接机器人，用 6768；6767 是引擎内部口。**

### 1.4 为什么要隧道？（跨机场景）

AstrBot 跑在云服务器，QDLS 跑在你家。服务器不能直接访问你家内网，于是：

```
[你的 PC]                                   [云服务器]
面板/网关 127.0.0.1:6768  ←── SSH 反向隧道 ──→  127.0.0.1:6768
                                              ↓ socat（容器访问宿主机）
                                         172.17.0.1:6768
                                              ↓
                                    [Docker 里的 AstrBot] 插件请求这里
```

三个概念：

- **SSH 反向隧道（`ssh -R`）**：由你的电脑主动连服务器，把「服务器上的某个端口」映射回自己。
  好处是**不需要公网 IP、不用开路由器端口**。
- **socat**：Docker 容器和宿主机不在同一个网络命名空间，`172.17.0.1` 才是宿主机在容器眼里的地址。
  socat 把 `172.17.0.1:6768` 转给 `127.0.0.1:6768`。
- **僵尸会话**：连接异常断开时，服务器那边的 sshd 子进程可能还占着端口，导致新隧道起不来。
  QDLS 的「重置云端链路」按钮就是专门杀这个的，服务端也配了 `ClientAliveInterval 30` 自动回收。

### 1.5 鉴权链路（为什么有两把钥匙）

```
① 配对码（32 位随机串，10 分钟，一次性）
   控制台生成 → 你手动填给插件 → 换取 token
        ↓
② Token（长期，形如 qdls_xxx）
   插件每次请求带 Authorization: Bearer <token>
        ↓
③ 服务端只存 token 的 sha256
   收到请求 → 算 hash → 比对 → 通过
```

为什么这么设计：

- 配对码**只活 10 分钟且用一次**，就算被看到，损失有限；
- token 是长期凭据，**页面永远不显示明文**（只在生成那一瞬间给你看一次）；
- 数据库里存的是哈希，文件被拷走也拿不到 token；
- 泄漏了就「接入」页撤销，旧 token 立刻 401。

### 1.6 三种接入方式，一条 API

| 入口 | 客户端 | 走什么 |
| --- | --- | --- |
| 网页 | 浏览器 | `/api/*`（本机，无需 token） |
| QQ | `astrbot_plugin_qdls` | `/api/v1/*` + Bearer |
| DSH | `qdls_mcp.py`（MCP 协议） | `/api/v1/*` + Bearer |

三者最终都落到同一套 `/api/v1`：

```
POST /api/v1/sing            → {job_id}
GET  /api/v1/jobs/{id}       → {state: queued|running|done|error}
GET  /api/v1/jobs/{id}/audio → mp3 字节流
```

### 1.7 为什么要「队列」

8 GB 显存只够同时跑一首。所以设计成：

```
请求1 → [排队] → [推理中] → 完成
请求2 → [排队] ─────────────┘（等前一个结束）
```

`state` 字段就是给你轮询用的；`queue` 告诉你后面还排着几首。
并发上限由 Gradio 的 `default_concurrency_limit=1` 保证，不会两张卡抢显存。

## 第二部分：处理流水线（参数挂在哪）

```
① 取源      歌名/链接 → 搜索 → 下载 → 截取 15~28 秒副歌
              ↑ clip_min / clip_max / full_song
                     ↓
② 分离       Demucs 去掉伴奏，留人声
              ↑ acappella（关掉就混回原伴奏）
                     ↓
③ 音高       RMVPE 提取音高曲线（F0）
              ↑ gate_enabled / gate_p95 / gate_max
                     ↓
④ 换音色     Whisper 编码器 + 扩散模型（SoulX-Singer）
              ↑ cfg / n_steps / fp16 / seed / pitch_shift / auto_shift
                     ↓
⑤ 修音       检测音高跳变，重跑异常片段
              ↑ repair_jumps / jump_semitones
                     ↓
⑥ 后处理     降噪 → 齿音压制 → 压缩 → 削峰
              ↑ denoise / deess_db / consonant_mix / comp_* / peak
                     ↓
                mp3
```

## 第三部分：参数样本（每个旋钮到底在干嘛）

> 下表的「实测」基于 RTX 5060 Laptop 8 GB + 24 秒片段。

### 3.1 音色与音高

| 参数 | 默认 | 作用 | 调大的效果 | 什么时候动 |
| --- | --- | --- | --- | --- |
| `voice` | `taffy` | 用哪个音色参考 | — | 换人唱就换它 |
| `pitch_shift` | `0` | 整体升降调（半音） | 声音更尖 | 男声唱女歌：**-5 ~ -12**；女声唱男歌：+5 ~ +12 |
| `auto_shift` | `false` | 按参考音高自动移调 | — | 不知道差几个半音时打开 |
| `lift_max` | `5` | 自动移调最多几个半音 | 允许更大跨度 | 原曲和参考差太多时加到 7 |
| `lift_ratio` | `0.78` | 自动移调的保守系数 | 更激进 | 一般别动，0.7~0.85 |

**为什么会有「升调」需求**：音色参考是女声、歌是男声时，直接用会闷。
移调把音高搬过去，但**移太多会失真**（像花栗鼠），所以有 `lift_max` 兜底。

### 3.2 生成质量（最影响观感）

| 参数 | 默认 | 范围 | 说明 |
| --- | --- | --- | --- |
| `cfg` | `2.5` | 1.5 ~ 5 | 贴合度。**大→更像参考音色但可能发硬**；小→自然但音色漂 |
| `n_steps` | `40` | 20 ~ 60 | 扩散步数。**大→细节多、慢**；20 步会有金属感 |
| `fp16` | `true` | 开/关 | 半精度，显存约减半、速度快，8 GB 必开 |
| `seed` | `42` | 任意整数 | 固定种子 = 可复现；换种子 = 微调音色细节 |
| `random_seed` | `false` | 开/关 | 每次随机，适合挑一版喜欢的 |

**经验值**：

- 想要「稳」：`cfg 2.2~2.6`、`n_steps 32~40`
- 想要「像」：`cfg 3.0~3.5`、`n_steps 45~50`（显存允许时）
- 想要「快」：`cfg 2.5`、`n_steps 24~28`，接受一点电音味

### 3.3 片段长度

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `clip_min` | `15` | 截取最短秒数 |
| `clip_max` | `28` | 截取最长秒数 |
| `full_song` | `false` | 整首（很慢，4 分钟歌要十几分钟） |

片段越长，**耗时和显存都线性上升**。8 GB 建议 `clip_max ≤ 28`；
6 GB 建议 `≤ 20`；想发整首就做好等很久的准备。

### 3.4 人声后处理

| 参数 | 默认 | 作用 | 调整建议 |
| --- | --- | --- | --- |
| `acappella` | `true` | 只出人声（清唱） | 关掉会混回原伴奏 |
| `denoise.enabled` | `true` | 降噪开关 | 底噪明显时开 |
| `denoise.strength` | `1.0` | 降噪强度 0~1 | **0.6 更自然**，1.0 可能发闷 |
| `deess_db` | `-3.5` | 齿音压制（「嘶」声） | 刺耳就降到 -5，过度会咬字不清 |
| `consonant_mix` | `0.25` | 保留原曲辅音比例 | 糊字就加到 0.35~0.45 |
| `comp_thr` | `-26` | 压缩阈值 dB | 想更「贴耳」用 -30，想保留动态用 -20 |
| `comp_ratio` | `4.5` | 压缩比 | 4~6 之间，太高会「压扁」 |
| `peak.enabled` | `true` | 削峰（防爆音） | 生成音频过载时必开 |
| `peak.ceiling_db` | `-3` | 峰值上限 dB | 平台音量偏小时可 -1.5 |

### 3.5 稳定性（防翻车）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `repair_jumps` | `true` | 检测音高跳变并重跑异常片段 |
| `jump_semitones` | `6` | 超过几个半音算「跳变」；调小更敏感但更慢 |
| `gate_enabled` | `false` | 音域超限直接拒绝，避免崩 |
| `gate_p95` | `650` | 95 分位音高上限（Hz） |
| `gate_max` | `750` | 绝对上限（Hz） |

**为什么要门限**：原曲音高超出模型训练范围时，会出现「尖叫」或直接 OOM。
门限相当于保险丝，宁可拒一首，也别炸显存。

## 第四部分：优化模式（四套预设）

| 模式 | 适用 | 关键设置 | 24 秒耗时（8 GB） |
| --- | --- | --- | --- |
| **稳（默认）** | 日常点歌、发 QQ | `fp16 on`、`n_steps 40`、`cfg 2.5`、`clip 15–28` | ≈ 60 秒 |
| **快** | 试歌、批量测试 | `n_steps 24`、`cfg 2.3`、`clip_max 20` | ≈ 35 秒 |
| **高质** | 想收藏的成品 | `n_steps 50`、`cfg 3.0`、`denoise 0.6`、`deess -4` | ≈ 90 秒 |
| **低显存** | 6 GB 卡 / 同时开别的 | `fp16 on`、`clip_max 18`、`n_steps 28`、关 `repair_jumps` | ≈ 45 秒 |

> 时间随显卡差异很大：台式 4070 大约只要笔记本的一半。

## 第五部分：选择取舍（这一节最重要）

### 5.1 三个互相拉扯的东西

```
        质量
        /  \
       /    \
    速度 —— 显存
```

你**不可能三个都要**。任何调参本质是在这个三角上选一个点：

- 加 `n_steps` → 质量↑ 速度↓ 显存基本不变
- 开 `fp16` → 速度↑ 显存↓ 质量≈不变（极少数情况细节略损）
- 加片段长度 → 质量↑（少拼接） 速度↓ 显存↑
- 加 `cfg` → 像↑ 但过头会「硬、塑料」

### 5.2 场景化推荐

| 你的情况 | 建议 |
| --- | --- |
| 只发 QQ 语音（压缩后细节本来就没了） | 别追高步数，40 步足够；片段 20 秒最划算 |
| 8 GB 笔记本 | `fp16 on`，`clip_max 28`，别开 `full_song` |
| 6 GB 或核显（不推荐） | `clip_max 16`、`n_steps 24`、关 `repair_jumps` |
| 想拿去投稿/成片 | `n_steps 50`、`cfg 3.0`、`denoise 0.6`，宁可等 |
| 多人同时点歌 | 接受排队；不要提高并发（会 OOM） |
| 音色不像 | 先调 `cfg`，再换参考音频质量（**唱声版**最好），最后才动 `n_steps` |

### 5.3 常见的「越调越差」

| 现象 | 多半是因为 | 怎么救 |
| --- | --- | --- |
| 电音味 / 机器人 | `n_steps` 太低 | 加到 36~40 |
| 声音发硬、塑料 | `cfg` 太高 | 降到 2.2~2.5 |
| 咬字糊 | `denoise` 太狠 + 辅音太少 | 降噪 0.6，`consonant_mix` 提到 0.35 |
| 高音刺、爆音 | 没开削峰 / `pitch_shift` 过头 | 开 `peak`，移调收回到 ±5 内 |
| 卡在 99% 或直接 OOM | 片段太长 | `clip_max` 减 6~8 秒，确认 `fp16` |
| 生成的语音像念经 | 参考音频本身是说话不是唱歌 | 换成**唱声**参考 |

## 第六部分：动手练习（建议按顺序做）

1. **固定其它变量，只改 `n_steps`**：24 / 32 / 40 各生成一次，听差别。
2. **只改 `cfg`**：2.0 / 2.5 / 3.2，感受「自然 ↔ 像」。
3. **开关 `fp16`**：看控制台显存读数（Home 页「显存 x/8.0 GB」）和耗时。
4. **只改片段长度**：15 / 22 / 28 秒，观察时间是否线性增长。

每做一次记一行：

```
n_steps=24  cfg=2.5  clip=22s  耗时 38s  显存 3.9G  评价：有点电音
```

做满 10 行，你就有了自己的「参数直觉」——这比看任何文档都管用。

## 术语表

| 词 | 意思 |
| --- | --- |
| **SVC** | Singing Voice Conversion，歌声转换：保留「唱什么」，改「谁在唱」 |
| **零样本** | 不用训练，给一段参考音频就能模仿音色 |
| **F0 / 音高曲线** | 每个时刻声音的高低，决定旋律 |
| **Demucs** | 分离人声/伴奏的模型 |
| **RMVPE** | 提取音高曲线的模型 |
| **扩散模型 / steps** | 一步步去噪生成，步数越多越精细也越慢 |
| **CFG** |  classifier-free guidance，控制「多听话地贴近参考」 |
| **fp16** | 半精度浮点，省显存提速 |
| **削峰 / limiter** | 把超过上限的波形压回来，防爆音 |
| **MCP** | 让 AI 客户端调用外部工具的标准协议（DSH 用它接 QDLS） |
| **反向隧道** | 内网机器主动连出去，把端口映射到公网服务器 |
